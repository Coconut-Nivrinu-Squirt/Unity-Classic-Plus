# Why Unity 7.4.0 as the base version?
This version was selected because it establishes a clear historical baseline from which future modifications can be evaluated individually. Maintaining this reference point helps ensure that the project remains focused on preserving the character, design philosophy, and user experience of Unity 7 while supporting future improvements. Preserving this last state helps prevent losing sight of the goal of this project (Preserving and improving the Unity 7 Version.)
The commit selected is git hash 0a4c35d25e8bd36cb7a07c6beced1254b10ba78a Available at the upstream source that is https://code.launchpad.net/unity with the tree hash as d7bd98f413448c10a4cb5e82bcdaa7852ecbd2ce.
### Selection Criteria that made 7.4.0 the definitive base source
Since this was the last version Canonical had endorsed before community maintenance became the primary means of sustaining Unity 7, it was selected as the project's baseline.

This preference is based on preserving a historically defined reference point rather than evaluating the quality of later community maintenance efforts.

Using the final Canonical-endorsed release reduces ambiguity when establishing project provenance and helps preserve the user experience, design philosophy, and desktop character that originally defined Unity.
Starting from this baseline also allows the project to evaluate later modifications individually rather than inheriting them automatically. This helps identify changes that improve interoperability and maintainability while reducing the risk of carrying forward unnecessary complexity or distribution-specific assumptions.
### Preservation Before Modernization

The primary objective of Unity Classic Plus is not immediate modernization. The first objective is understanding how Unity was originally designed, built, and maintained.

By establishing a thorough understanding of the original architecture and design decisions, future improvements can be made with confidence and purpose rather than through assumption or repeated compatibility workarounds.

This approach helps preserve the character of the desktop environment while reducing unnecessary complexity. It also encourages solutions that address underlying causes rather than relying on long-term patch maintenance.

Modernization remains an important goal for the project, but it should occur only after the existing system is understood well enough to ensure that changes continue to support the project's core values and user experience.
